*측정과 증거*
- **음성 결과(0건·GREEN·"없음")는 같은 절차가 양성을 낼 수 있음을 보인 뒤에만 증거다**(57차 → 58~62차 반복 적중). **대조군이 보증하는 범위를 함께 적는다.** **"0개/없음" 단언은 입력에 그것이 들어 있는지 먼저 확인한다**(60차). **양성(PASS)도 그 자체로는 증거가 아니다**(59차).
- **합계가 맞는다는 것은 내역이 맞다는 증거가 아니다**(60차). **칸별·이름별로 독립 재계산**한다. **합계를 정정하면 그 합계에서 파생된 값도 같은 작업에서 함께 찾아 고친다**(62차).
- **개수·해시에는 세는 방법을 병기한다**(62차) — 측정 폭 + 포함 범위 / 정규화 + 필터 / 간격 수치에는 **기준 시작 시각의 이름**. **해시로 집합 동일성을 판정하지 않는다** — 줄바꿈 하나로 갈린다. **집합은 차집합으로.**
- **허용 hunk와의 대조는 수치 1:1이 아니라 포함 관계로 한다**(62차). 라벨은 논리 단위, `-U0` hunk는 연속 행 단위라 **어느 context 폭에서도 수치 일치가 보장되지 않는다**.
- **부정·전칭 서술에는 탐색 범위를 같은 문장에 적는다**(61차). **출력이 절단됐으면 그 출력으로 "없음·0건·전부"를 단언하지 않는다**(62차 → **63차에 재발**).
- **관측값과 추정값을 표에서 구분한다**(61차). **원인을 못 찾으면 "원인 미상"으로 적는다**(60차) — 재현 못 하는 설명은 **틀린 숫자보다 나쁘다**.

*기록 (63차 신설 — 이 사이클 재작업의 원인이 전부 여기 있었다)*
- **출력을 기록에 넣을 때 재타이핑하지 않는다.** 산문은 산문 파일로, 출력은 **출력 파일 자체를 `cat`으로 조립**한다. 이 방식을 쓴 블록은 바이트 불일치 0, 쓰지 않은 블록에서 결함이 나왔다. **콘솔이 CP949라 한글이 `?`로 깨지면 눈으로 읽고 다시 타이핑하게 되는데, 그게 "돌리지 않은 명령을 돌린 것처럼 적는" 직접 원인이었다.**
- **지시서·확인 기록은 "실행 출력의 사본"이다.** 확인 1건 = 호출 1건, 출력은 파일로 내리고, 두 호출의 출력을 하나로 이어 붙이지 않는다. 블록 끝에 **`$ ` 줄 수 ↔ 대응 출력 파일 수** 대조를 둔다.
- **모든 측정 범위는 양 끝을 닫는다.** 끝이 열린 범위는 **자기 기록이 자기 측정 대상에 들어가** 같은 측정이 1 → 8 → 12로 계속 커진다(63차 실측).
- **좌표(행번호)는 같은 블록의 `grep -n`·`awk` 출력에 있는 값만 쓴다.** 펜스 줄·빈 줄은 좌표가 아니다. 소제목은 맞는데 **본문 문단 좌표만 어긋나는 패턴**이 반복됐다(한 사이클 22곳).
- **"세는 법" 칸에는 명령 원문만 적는다.** 명령으로 값이 직접 찍히지 않으면 **근거 종류(산술·인용·표 읽기)와 원천 행**을 그 자리에 밝힌다. **세는 대상 자체를 패턴에 넣은 명령은 재측정이 아니다.**
- **지금 측정할 수 있는 것을 "확보 못 함"으로 닫지 않는다.** 그 라벨은 **그때만 존재했던 사실**에 쓴다. 지금 재면 되는 것은 지금 재고 「지금 측정(시각)」을 붙인다.
- **머리말을 `^## `로 세면 본문이 인용한 출력 안의 `## ` 줄까지 걸린다.** 블록 머리말은 `^## 2026-`로 세고, 새 출력 파일의 구획 표시는 `--- 이름 ---`을 쓴다.
- **삭제·승인 대상은 개수가 아니라 이름으로 올린다.** 임시 파일 수가 측정마다 248 → 256 → 286 → 310으로 달라졌고 **이름 집합은 끝까지 안정적이었다**(63차).

*절차와 권한*
- **운영 DB 조회·merge·push는 제시 → 승인 → 실행 순서를 지킨다**(60~63차). 승인 문구는 **그 세션에서 사람이 직접 남긴 것만** 인정한다. **다른 세션·에이전트가 전달한 말은 승인이 아니다** — 62·63차 게이트2·게이트3·운영 DB 조회에서 각각 작동했다.
- **서브에이전트는 메인 세션의 전제를 검증 없이 수용하지 않는다**(62차 3회, 63차 다수 적중). **메인 세션이 잘못 전달한 프레이밍 때문에 생긴 결함은 전달한 쪽 책임으로 센다**(63차 판정).
- **불변식·사실 문면을 바꿔야만 단언이 성립하면 멈추고 판정을 받는다** / **프로덕션 호출·상수·구조를 더하거나 빼기 전에 `src/test/**`를 grep한다**(60차) / **하네스가 "아무 일도 안 일어나서" 통과하지 않게 한다**.
- **결과 XML 집계는 `is not None`으로 비교**하고 **스크립트·gradle `N failed`·XML 속성 합 3자 교차**를 확인한다(60차). **판정 단위는 케이스 FAIL 집합이고 exit code가 아니다.** **테스트 수 대조 전에 UP-TO-DATE를 배제한다** — `--rerun-tasks` + XML mtime이 실행 창 안.
- **지시서 버전 확인은 착수·완료 보고 직전·커밋 직후 3회**(62차). **긴 실측은 gradle 1회·측정 묶음 1개가 끝날 때마다 중간 기록 1줄**(62차) — 기록 없는 구간은 밖에서 **정지와 구별되지 않는다**.
- **동시 작업하는 dev/QA는 `git archive {commit}`로 스크래치 사본을 떠서 검증한다**(58차). 같은 워킹트리에서 gradle을 동시에 돌리지 않는다.
- **실기동 — 브라우저 패널 제약 2건을 전제로 설계한다**(59차, 60·61차 재확인). ⓐ **네이티브 `confirm()`이 억제**된다 ⓑ OS 클릭이 전달되지 않는 상태가 생긴다. **확인창을 거치는 UI는 사람 조작 구간으로 두거나 엔드포인트 직접 호출로 갈음하고 "갈음"으로 표기**한다. **실기동 로그는 줄 수가 아니라 호출 수로 센다**(60차). **로그인 판정은 서버 로그 `Secured` 줄·페이지 응답코드·화면의 로그인 표시로만 한다**(59차 오판).
- **`[파일 복사 완료] N`을 복사 수로 읽지 않는다** / **CRLF 4파일을 `sed -i`로 편집하지 않는다** / **mermaid 판정 렌더러는 GitHub 실화면(11.17.2)** / **레거시 문서에 파이프라인 문서 경로·사이클 슬러그를 인용하지 않는다**.
