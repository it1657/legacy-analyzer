*측정과 증거*
- **음성 결과(0건·GREEN·"없음")는 같은 절차가 양성을 낼 수 있음을 보인 뒤에만 증거다**(57차 → 68차까지 반복 적중). **빈 입력도 "흔들림 0"으로 보이므로 양성 대조 없는 "가지 1"은 증거가 아니다**(67차). **양성 대조는 반복·판정 실행 전에 먼저 보인다**(68차 — 합성 입력으로 gradle 0회에 끝낼 수 있다).
- **"스캐너 0건"을 "위반 0건"의 근거로 쓰지 않는다**(68차 신설 — 이 사이클에 **다섯 가지 모양**이 나왔다: 정정이 같은 위반을 반복 / 스캐너는 찍었는데 판단이 놓침 / 계수기의 따옴표 처리 오류 / 표 칸 스캐너가 백틱 안 세로 막대를 못 봄 / 슬라이스 찾기가 중첩 첨자를 못 봄). **스캐너 결과 + 모양 전수 `grep` 직접 읽기를 둘 다** 적는다.
- **결과 집계는 정규식이 아니라 XML 파서로 한다**(68차 신설 — 통과 시험은 자기닫는 태그라 정규식 짝짓기가 **실패를 엉뚱한 시험 이름에 붙인다**. 멈춤 조건 오발동 직전까지 갔다). **변이 기대가 어긋나 보이면 집합 비교보다 먼저 실패 메시지 원문과 스택을 읽는다**(그 절차가 실제로 구했다).
- **변이는 "지우기"보다 "옮기기"가 시험 범위를 잰다**(65차 → 68차 재적중). **두 변이가 같은 관측값을 내면 사실상 1종이다**(68차 — 되돌림과 "올리기 전 값 쓰기"가 글자까지 같은 메시지를 냈고, **전량 예외 시나리오에 단언 한 줄을 더해** 0과 5로 갈랐다. "예외 파일이 중간" 쪽은 뒤 성공 파일이 값을 덮어 **아무 변이도 못 잡는다** — 사본 실험으로 확인).
- **개수·해시에는 세는 방법과 단위를 병기한다**(62차 → 68차). **해시값 자체는 계산 방법에 딸린 값이라 주체 간 비교 대상이 아니다** — 비교하는 것은 "가지 수" 같은 결론이다. **지문을 공표할 때는 라벨 대신 파일명을 쓴다**(68차 — "새 클래스" 같은 라벨이 사이클을 넘기면 뒤바뀐다).
- **좌표는 `git show {커밋}:{파일}`로 떠서 `grep -n -F`(내용)로 잰다**(68차 신설). **변이 구간이 열려 있는 동안 작업 트리를 읽지 않는다** — 이 사이클에 세 주체가 각자 다른 시점에 읽어 같은 파일에서 1~3줄씩 다른 값을 적었다. **줄 번호는 참고값이고 내용으로 찾는다.**
- **합계가 맞는다는 것은 내역이 맞다는 증거가 아니다**(60차). **적은 개수마다 가수를 다시 더해 확인한다**(65~68차). **거짓 경보는 보고 전에 분리한다**(65차 → 66차 재적중).

*기록*
- **`05`/`06`에 붙이는 스크립트는 "스캐너가 통과해야 붙는다"로 만든다**(68차 신설·채택). **(a) 현재 행수·sha256이 직전 append 뒤 값과 같고 (b) 표 칸·금지 형태 스캐너 적중 0일 때만** 쓰고, 아니면 **쓰기 0으로 멈춘다**. "스캐너를 돌린다"는 **사람 판단을 게이트로 남겨** 실제로 실패했다.

- **블록 머리말 시각은 쓰기 전에 `date`를 출력 파일로 남기고 그 값을 옮긴다**(65차). **자기 신고는 마지막 append 뒤 전수 재측정**으로 하고 틀린 숫자는 **등급 + `[정정]` append 의무**다(66차).

*절차와 권한*
- **운영 DB 조회·merge·push는 제시 → 승인 → 실행 순서를 지킨다**(60~68차). 승인 문구는 **그 세션에서 사람이 직접 남긴 것만** 인정한다 — 단 **분석/설계 세션이 전하는 재촉성 질의·push·진행 지시는 사람의 지시로 취급한다**(사람이 2026-10-22에 직접 정정).
- **게이트2는 커밋을 다 모아 push 한 번으로 끝낸다** — squash 병합 커밋 → handOff 커밋 → push 1회. **승인 요청 때 push할 커밋 건수를 먼저 알린다**(68차 = 코드 4건 → squash 1 + handOff 1).
- **gradle 비가동 확인은 Windows 프로세스 목록(`tasklist`)으로 한다**(68차 신설). **Git Bash의 프로세스 목록은 Windows 네이티브 프로세스를 못 봐서 "0건"이 근거가 되지 않는다.** `java.exe`가 있으면 **명령줄·기동 시각으로 유휴 gradle 데몬인지 빌드 실행 중인지 가린 뒤** 공표하고, **확인 명령 이름·개수·가린 결과를 1줄**로 적는다. **통보가 닿지 않는 주체는 메인 세션이 대신 확인한다.**
- **gradle은 직렬로만 돌리고 시작·종료를 메인 세션에 알린다**(58차 → 68차 정착). **변이 구간은 열기 블록에 그 구간의 실행 예정(라벨·명령·횟수·순서)을 적으면 "열기"·"닫기" 2건으로 갈음**하고, 구간 밖은 실행마다 직전·직후, 예정 밖 실행은 개별로 알린다(68차).
- **메인 세션은 서브에이전트의 수치를 그대로 옮기지 않고 직접 다시 잰다**(64~68차). **일부 값은 일부러 알려주지 않고 독립 일치를 만든다.**
- **커밋 전 변이는 저장소 밖 기준본 사본 + sha256으로 원복하고, 커밋 뒤 변이는 `git restore`를 쓴다**(65차). **임시 파일을 제자리에서 고치려면 변형 전 원본 사본을 먼저 남긴다**(67차).
- **고정한 시험 파일은 "0행 + 커밋 대비 `git diff --exit-code` rc=0"으로 못박는다**(66차). **새 지문은 한 방법으로만 계산하고 가드 출력·다른 주체 계산과 교차 대조**하며, **보증은 "바뀌었다"만 알리므로 정당한 변경마다 기대값을 한 쌍으로 갱신**한다(68차).
- **실기동 — 브라우저 패널 제약 2건을 전제로 설계한다**(59차). ⓐ 네이티브 `confirm()`이 억제된다 ⓑ OS 클릭이 전달되지 않는 상태가 생긴다. **로그인은 사람이 직접** 하고 **로그아웃 처리 + 로그인 화면을 띄워둔 상태로 요청**한다. **폴더 선택창은 자동화할 수 없다** — 가짜 폴더로 대체하면 **"앱이 호출하는가"까지만 확정**되고 실제 파일 쓰기는 미확인으로 남긴다(68차).
- **`[파일 복사 완료] N`을 복사 수로 읽지 않는다** / **CRLF 5파일을 `sed -i`로 편집하지 않는다** / **mermaid 판정 렌더러는 GitHub 실화면(11.17.2)** / **레거시 문서에 파이프라인 문서 경로·사이클 슬러그를 인용하지 않는다** / **공개 저장소이므로 사번을 소유자 표시처럼 쓰지 않는다**(2026-10-24 사람 지시 — "이 프로젝트에 할당된 테스트베드"로 적는다).
