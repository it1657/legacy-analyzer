# 진행 현황 핸드오프 — 현재 상태 (2026-10-24 기준)

> **① 상태**: `scenario_3`(선택형)만 유일한 활성 트랙. 마지막 완료 사이클은 **67차 `2026-10-interrupted-file-reanalysis`** — **멈춤 판정과 파일 처리 사이의 "틈"에 걸린 파일이 재분석 대기에서 빠지던 문제를 고치고**(O43 포함) **`analyzeFile` 밖에서 예외·`Error`로 끝난 파일도 실패로 세게 했다**(squash **`41fdbc8`**, `origin/master` 반영). 프로덕션은 `MainApiController.java` 한 파일 **+20/−2**, 회귀 **146클래스/1255건/실패 0**(반복 30회 흔들림 0). 진행 중인 사이클 **0건**. **다음 1순위는 서버 배포 안건**(67차 게이트2 확정)이고 그다음이 **O15 + 건너뜀 칸 불일치(O59)** 다 — 착수는 사람이 지시할 때다.
> **② 막힌 것**: `scenario_3` 롤아웃 계획이 현재 권한 구조와 안 맞는다(전제 붕괴 3건) — 계획 개정은 PM/사람 결정 사항. PGX Qwen3 샌드박스는 계정 권한 확인이 안 돼 착수 불가.
> **③ 사람이 할 일**: (1) `scenario_3` 롤아웃 계획을 고칠지 결정, (2) PGX 서버 권한 확인, (3) **58차 배포 시 첫 기동 로그로 옛 표시명 자동 정리를 확인**(§4-B), (4) **배포로 "빈 완료 이력"이 멎는지 확인** — 운영 이미지에는 원본 소실 가드가 없어 **지금도 재발 가능하다**(§1·§4-B), (5) **61차 배포 후 분석 대상 수 증가(12 → 14형) 확인**, (6) **62차 배포 후 429·529 과부하 시 체감 소요 시간 증가 확인**, (7) **65차 배포 후 중복 요청 거절 문구 3종이 화면에 뜨는지 확인**, (8) **66차 배포 후 새 완료 이력의 "총 파일"이 실제 파일 수로 오르고 PPT "주석 생성 완료 %"가 내려가는지 확인**(과거 행은 그대로다), (9) **67차 배포 후 일시정지·취소 직후 멈춘 파일이 재개 때 다시 분석되는지 확인**(대기 목록에 그 파일이 남아야 한다 — §1), (10) **67차 push 뒤 `Bash(git push:*)` 재잠금**과 **임시 폴더 삭제 지시(선택)** — 이 사이클 `irf-` 9개와 이전 사이클 잔존 별건이 있고, 삭제는 사람이 개발 세션에서 직접 지시할 때만 한다. **추적 보존은 이번에 미리 끝냈다**(지문 계산 스크립트 전문을 `05`에 인용 — 지워도 근거가 끊기지 않는다).

**이 파일은 "지금 상태"만 담는 스냅샷이다.** 매 사이클이 끝날 때 통째로 다시 쓴다(append 아님).

- **음성 결과(0건·GREEN·"없음")는 같은 절차가 양성을 낼 수 있음을 보인 뒤에만 증거다**(57차 → 67차까지 반복 적중). **양성(PASS)도 그 자체로는 증거가 아니다**(59차). **사전 값이 0이면 전후 비교로 "고쳤다"를 보일 수 없다**(64차). **빈 입력도 "흔들림 0"으로 보이므로 양성 대조 없는 "가지 1"은 증거가 아니다**(67차).
- **변이는 "지우기"보다 "옮기기"가 시험 범위를 잰다**(65차 신설, 66·67차 재적중). 두 방식을 함께 돌린다. **정비가 감시를 느슨하게 한 것이 아닌지 반대 방향 변이로도 확인한다**(66차 M1·M2).
- **합계가 맞는다는 것은 내역이 맞다는 증거가 아니다**(60차). **적은 개수마다 가수를 다시 더해 확인한다**(65~67차).
- **개수·해시에는 세는 방법과 단위를 병기한다**(62차 → 66차 확정 → 67차에 세 주체가 각자 단위를 정의해 묶기 수치 차이를 설명했다). **해시로 집합 동일성을 판정하지 않는다** — 집합은 차집합으로. **해시값 자체는 계산 방법에 딸린 값이라 주체 간 비교 대상이 아니다**(67차 — 비교하는 것은 "가지 수" 같은 결론이다).
- **인용 좌표·개수·단위는 전달 전에 직접 열어 확인하거나 【보고값(미검증)】 라벨을 붙인다**(66차 신설). **좌표 점검은 사례 ID만이 아니라 칸 라벨까지 대조한다**(67차 신설 — 사례 ID만 보면 인접 항목을 가리킨 좌표가 안 잡힌다).
- **마크다운 표의 `\|`를 grep BRE에 넣으면 교대가 되어 전체 줄에 걸린다**(62차 → 64차 → 67차 재발). `awk` 정본이나 `grep -F`·`-E`를 쓴다.
- **바이트·고정 폭 자르기를 쓰지 않는다**(66차 확정 → 67차에 세 주체가 또 걸렸다). **포함**: 길이 0 또는 임의 폭 인자를 가진 모든 자르기(`cut -c`·`cut -b`·`awk substr`·`printf "%.Ns"`·`head -c`·`fold -b`·PowerShell `Substring`·파이썬 슬라이스·정규식 반복 상한 `{0,N}`). **제외**: `cut -f` · 길이가 패턴으로 정해진 `grep -o` · 리스트 슬라이스(`sys.argv[1:]`)는 경계로 공개. **대신**: 긴 줄은 **파일로 받아 전문 인용**.
- **관측값과 추정값을, 전달받은 값과 직접 잰 값을 표에서 구분한다**(61·64차 — 【측정】/【보고값(미검증)】).
- **거짓 경보는 보고 전에 분리한다**(65차 → 66차 재적중). 양성 대조 폴더가 섞여 "흔들림 2"로 보이거나 `.txt` 파일이 glob에 걸려 회차 수가 늘 수 있다 — **분리 전 수치로 "상대 주장이 틀렸다"고 쓰지 않는다.**

*기록*
- **출력을 기록에 넣을 때 재타이핑하지 않는다**(63차). 출력 파일 자체를 `cat`으로 조립한다. **증거 XML 사본은 `cp -p`로 떠서 mtime을 보존한다**(65차).
- **임시 폴더를 지우면 끊길 추적을 사이클 안에서 미리 닫는다**(67차 신설). 시험 주석·기대값·지문 계산이 **임시 폴더 안 스크립트를 부르면 그 전문을 개발 기록에 인용**한다 — 삭제 직전에 급히 옮기지 않는다. 가려내기 기준은 "시험 소스·기대값·`07` 승계가 인용할 근거 수치의 원천인가"다.
- **블록 머리말 시각은 쓰기 전에 `date`를 출력 파일로 남기고 그 값을 옮긴다**(65차). 앞 블록보다 이르면 멈추고, 마감에 **단조성 1줄**을 넣는다.
- **append-only 파일은 작업 트리끼리만 해시를 비교한다**(65차). `05`·`06`은 **CRLF가 섞여** 있고 `06`은 git에서 **`-text`**다 — 대조는 **`diff --strip-trailing-cr`**로 하고 rc를 적는다.
- **각 TASK 착수 직전에 메인 세션이 `05`·`06`의 행수와 `head -n` 해시를 먼저 공표하고, 하위 에이전트가 그 값과 대조해 시작한다**(66차 신설 → 67차에 10/10·전부 일치로 정착). **`_status.md` 행수는 공표하지 않는다** — PL이 수시로 갱신해 두 번 어긋났다(67차).
- **자기 신고는 마지막 append 뒤 전수 재측정으로 하고, 숫자의 정확성까지 요구한다**(66차 확정). **총수 재확인은 전수 재스캔을 대신하지 못한다.** 틀린 숫자는 그것만으로 Fail이 아니고 **등급(P2~P3) + `[정정]` 블록 append 의무**다.
- **긴 히어독은 한 명령 8KB 안쪽으로 쓴다**(66차 → 67차 실측: 9,027B·11,028B는 성공하고 12,082B는 `Exit code 2` + `unexpected EOF`로 **파일이 만들어지지 않는다**). **따옴표 없는 히어독은 역슬래시뿐 아니라 백틱도 먹는다**(67차 실측) — 내용에 둘 중 하나라도 있으면 `<<'EOF'`.
- **삭제·승인 대상은 개수가 아니라 이름으로 올린다**(63차). 개수는 **세는 시점을 함께 적는다**(65~67차 — 같은 폴더가 측정 시각에 따라 달라졌고, 메인 세션이 중간에 만든 폴더가 하위 에이전트 집계에 잡혔다).

*절차와 권한*
- **운영 DB 조회·merge·push는 제시 → 승인 → 실행 순서를 지킨다**(60~67차). 승인 문구는 **그 세션에서 사람이 직접 남긴 것만** 인정한다 — 단 **분석/설계 세션이 전하는 재촉성 질의·push·진행 지시는 사람의 지시로 취급한다**(사람이 2026-10-22에 직접 정정했다).
- **게이트2는 커밋을 다 모아 push 한 번으로 끝낸다** — squash 병합 커밋 → handOff 커밋 → push 1회. **승인 요청 때 push할 커밋 건수를 먼저 알린다**(67차 = 코드 5건 → squash 1 + handOff 1).
- **커밋 전 변이는 저장소 밖 기준본 사본 + sha256으로 원복하고, 커밋 뒤 변이는 `git restore`를 쓴다**(65차). 기준본 sha256은 **변이 시작 전에 공개**한다. **임시 파일을 제자리에서 고치려면 변형 전 원본 사본을 먼저 남긴다**(67차 — 역방향 증명과 충돌하던 규칙을 이 문면으로 정리했다).
- **공용 작업 트리에서는 변이 구간의 시작·종료를 알린다**(65차). **gradle은 직렬로만 돌리고 시작·종료를 메인 세션에 알린다**(58차 → 67차 정착).
- **메인 세션은 서브에이전트의 수치를 그대로 옮기지 않고 직접 다시 잰다**(64~67차 — 이 방식으로 dev·QA 양쪽에서 기록 결함을 거듭 잡았다). **일부 값은 일부러 알려주지 않고 독립 일치를 만든다**(67차에 회귀 건수·흔들림·묶기 수치에서 3자 독립 일치가 나왔다).
- **정본 명령은 쓰기 전에 표본으로 시험 실행한다**(64·65차). **서브에이전트는 메인 세션의 전제를 검증 없이 수용하지 않는다.**
- **고정한 시험 파일은 "0행 + 커밋 대비 `git diff --exit-code` rc=0"으로 못박는다**(66차). 양성 대조를 함께 둬서 rc=0이 "명령 미실행"과 구분되게 한다.
- **새 지문(해시)은 작업 트리 사본에서 한 방법으로만 계산하고 가드 출력·다른 주체 계산과 교차 대조한다**(66차 → 67차 IR-17로 "LF 정규화 → `git hash-object`" 단일 방법 확정). 하나라도 다르면 커밋 전에 멈춘다.
- **결과 XML 집계는 스크립트·gradle 요약·XML 속성 합 3자 교차**로 확인한다(60차). **`--rerun-tasks` + XML mtime이 실행 창 안**(64차: 나노초로 찍는다). **창끼리 겹치지 않는지도 본다**(67차).
- **실기동 — 브라우저 패널 제약 2건을 전제로 설계한다**(59차). ⓐ 네이티브 `confirm()`이 억제된다 ⓑ OS 클릭이 전달되지 않는 상태가 생긴다. **로그인 판정은 서버 로그 `Secured` 줄·응답코드·화면 표시로만 한다.**
- **`[파일 복사 완료] N`을 복사 수로 읽지 않는다** / **CRLF 5파일을 `sed -i`로 편집하지 않는다** / **mermaid 판정 렌더러는 GitHub 실화면(11.17.2)** / **레거시 문서에 파이프라인 문서 경로·사이클 슬러그를 인용하지 않는다**.
