## 1. 지금 시스템은 어떻게 동작하나 (핵심 사실)

| 항목 | 현재 사실 |
|---|---|
| Provider 선택 | **런타임 리졸버**(`LlmClientResolver`)가 DB `llm_model_options`의 `provider` 값으로 매 호출마다 구현체를 고른다. `llm.provider`는 **DB에 없는 모델명에 대한 폴백 기본값**으로만 남아 있다 |
| 모델 목록 | DB + 관리자 CRUD(ADMIN 전용). 사용자 조회는 `GET /api/config/llm-models`, 설치 여부는 `/local-installed`(TTL 캐시, `available=false`는 "설치 없음"이 아니라 **"확인 불가"**) |
| 접근 권한 | **Anthropic = 허가제**(API 키 + `ANTHROPIC_USER` Role, admin은 항상 통과) / **로컬 = 기본 개방** |
| 비상용(임시) 모델 목록 | 하드코딩 임시 목록이 표시된 상태에서는 **분석이 시작되지 않는다**(59차). 두 진입점 모두 안내 alert 1회만 띄우고 `/api/start-analysis`를 호출하지 않는다 |
| **폴더 제외 판정 — 61차 신규** | **분석 루트 기준 상대경로**로 본다(종전은 절대경로 전체). 사용자가 고른 **출력 폴더명이 `out`** 이거나 **경로 위쪽에 `build`·`bin`·`rebuild`** 같은 이름이 있기만 해도 그 아래 전부가 제외되어 "분석 대상 파일 0개"로 끝나던 문제가 사라졌다. 제외 대상은 **프로젝트 안쪽의** 빌드 산출물 폴더다. 네 스캔 지점이 `isAnalysisTarget` 하나를 공유한다 |
| **분석 대상 증가 — 61차 의도된 변화** | 위 변경으로 **프로젝트 루트의 `build.gradle`·`.github/workflows/*` 등이 새로 대상에 들어간다**(실측 12 → 14). 프로젝트 **안쪽**의 `build/`·`target/`·`node_modules/`·`out/` 은 그대로 제외된다. **분석 파일 수가 늘면 LLM 호출도 는다** |
| **경로 토큰 비대칭 — 61차 확인** | 스캔 쪽(`isSupportedFile`) **25토큰·슬래시로 감싼 요소 일치·대소문자 무시** / 복사 쪽(`performCopy`) **20부분문자열·대소문자 구분**. `out`·`bin`은 스캔 쪽에만, `rebuild`는 복사 쪽에만 걸린다. **두 목록을 같은 것으로 보면 오판한다** |
| **실패 화면 — 61차 신규** | 실패 경로가 성공 화면에서 분리됐다. 분석 대상이 없으면 **완료 패널이 닫히고**(`block` → `none`) `#errorPanel`에 `⚠️ 에러 발생` + `❌ 분석 실패: {사유}`가 뜨며 **`CLAUDE.md 보기`·`PPT 다운로드` 버튼이 안 나온다**. 서버 로그에는 `[분석 대상 없음]`으로 **분석 루트를 함께** 남긴다(화면 문구에는 경로를 넣지 않는다) |
| 원본 소실 | `SessionSourceAvailability`가 재개 전에 판정한다. **전량 소실이면 `SOURCE_MISSING`으로 거부**, **일부 소실이면 남은 파일만 재개**하고 소실분은 실패로 기록한다. **기록은 삭제하지 않는다** |
| 재개 카운터 | 재개 시작 때 처리 수를 **`총계 − 대기 수 + 소실 수`로 다시 세고** 실패 수는 0에서 다시 센다. 총계 상한 클램프는 두지 않는다(경고 로그만). **원본이 사라진 파일도 "끝난 파일(실패)"로 센다.** 이전 재개에서 확정된 실패는 재기준 뒤에도 유지된다(`[재개 이월 실패]`) |
| 오류 분류 | `ApiErrorHandler.classifyError()`가 **메시지보다 상태 코드를 먼저** 본다. `RetryHandler`는 같은 분류기에 위임한다. **401은 `API_AUTHENTICATION`이고 재시도하지 않는다** |
| 실패 사유 집계 | 집계 키가 **메시지 전문이 아니라 `errorType`**이고 표시용 이름표가 분리돼 있다(9종). 전량실패 안내에 타임스탬프를 넣지 않는다 |
| 종단 세션 보호 | 끝난 분석에 대한 일시정지는 `SESSION_TERMINAL`로 거부되고 상태를 바꾸지 않는다 |
| failover | 크레딧 소진 시 관리자 지정 모델로 이어갈지 사용자 컨펌 — `AWAITING_FAILOVER_CONFIRM`(종료 상태 아님) |
| RAG | A안(패키지 구조 압축) + B안(코드 내용 청킹) 독립 토글 2개 |
| 토큰 집계 | **세션 키 맵으로 격리**(56차). 재개 경로는 리셋하지 않는다. 키가 같으면(동일 경로 동시 분석) 여전히 합산된다(§4-B 이월) |
| 비용 계산 | **세션이 실제로 라우팅되는 provider로 판정**(56차). `resolveEffectiveProvider()` 하나로 모으고 계약 테스트로 고정 |
| 모델 단가 | `AnthropicModelPricing`이 **정확 키 → `claude-` 패밀리 → 미지 모델은 최고 단가 + WARN** 순으로 결정. **단가 문자열의 정본은 이 한 곳뿐**이고 API가 `pricing` 필드로 내린다 |

**다음 사이클을 열 때 그대로 적용할 규칙**(55~61차 확정, 상세는 history):
- **음성 결과(0건·GREEN·"없음")는 같은 절차가 양성을 낼 수 있음을 보인 뒤에만 증거다**(57차 확립 → 58~61차 반복 적중). **대조군이 보증하는 범위를 함께 적는다.**
- **"0개/없음" 단언은 입력에 그것이 들어 있는지 먼저 확인한다**(60차). **양성(PASS)도 그 자체로는 증거가 아니다**(59차).
- **합계가 맞는다는 것은 내역이 맞다는 증거가 아니다**(60차). **칸별·이름별로 독립 재계산**한다.
- **부정·전칭 서술에는 탐색 범위를 같은 문장에 적는다**(61차 G-23e). "없다·0건·뿐·전부·확보 불가"는 **위치·방법·시각 구간·검색어**를 동반한다. 범위를 적을 수 없으면 **"찾지 못함(범위 미정)"**으로 쓴다. 화면 관측은 **패널 안 / 보이는 영역 / 페이지 전체** 중 어느 범위인지 밝힌다.
- **관측값과 추정값을 표에서 구분한다**(61차). 상태 API에서 끌어낸 값을 "화면" 열에 적으면 다음 사람이 관측으로 읽는다. **열 제목이 관측을 뜻하면 추정은 그렇다고 적는다.**
- **산출물 관문을 정리보다 먼저 만든다**(61차 G-23a). 인스턴스를 끄기 전에 "무엇을 파일로 남겼는가" 표를 만들면 빈 칸을 **살아 있는 동안** 메울 수 있다. 61차 실증: 빈 칸 17건을 그 자리에서 채웠다. **단 표의 행은 DoD 문면 항목뿐 아니라 절차상 "필수" 항목도 포함해야 한다** — 행이 없으면 관문이 못 잡는다.
- **선택자가 `null`/빈 값을 내면 그 자리에서 고쳐 다시 받는다**(61차 G-23c). 끄고 나서는 복구할 수 없다.
- **관측 원문은 그 자리에 파일로 내린다**(61차 G-27). 세션 기록에만 두면 나중에 되살려야 하고, 되살릴 수 없는 것도 생긴다. 해시를 적을 때는 **입력 정의**(파일 바이트인지 개행 제거 문자열인지)를 함께 적는다.
- **원인을 못 찾으면 "원인 미상"으로 적는다**(60차). 재현 못 하는 설명은 **틀린 숫자보다 나쁘다**.
