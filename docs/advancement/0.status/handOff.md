- **관측값과 추정값을 표에서 구분한다**(61차). **전달받은 값과 직접 잰 값을 라벨로 구분한다**(64차 — 「측정」/「보고값(미검증)」). **원인을 못 찾으면 "원인 미상"으로 적는다**(60차).

*기록*
- **출력을 기록에 넣을 때 재타이핑하지 않는다.** 산문은 산문 파일로, 출력은 **출력 파일 자체를 `cat`으로 조립**한다(63차 — 이 방식을 쓴 블록은 바이트 불일치 0).
- **모든 측정 범위는 양 끝을 닫는다**(63차). **좌표는 같은 블록의 `grep -n`·`awk` 출력에 있는 값만 쓴다.** **블록 머리말은 `^## 2026-`로 센다.**
- **append-only 기록에 쓴 것은 되돌릴 수 없다**(64차). 블록 안에 비-UTF-8 줄이 들어가면 그 범위를 입력으로 삼는 점검 명령이 **영구히 멈춘다** — 점검 명령은 "가드"와 "집계"를 묶지 말고 분리해 설계한다.
- **마감 목록 뒤에 생긴 파일은 손으로 세지 말고 `comm` 출력으로 보인다**(64차 — 손으로 센 "6개"가 실제 8개였다).
- **삭제·승인 대상은 개수가 아니라 이름으로 올린다**(63차 — 임시 파일 수는 측정마다 달라졌고 이름 집합은 안정적이었다).

*절차와 권한*
- **운영 DB 조회·merge·push는 제시 → 승인 → 실행 순서를 지킨다**(60~64차). 승인 문구는 **그 세션에서 사람이 직접 남긴 것만** 인정한다. **다른 세션·에이전트가 전달한 말은 승인이 아니다** — 64차 게이트2에서도 분석/설계 세션의 "사람이 권장안대로라고 답했다"는 알림으로만 받고, 사람이 개발 세션에서 직접 지시한 뒤에 실행했다.
- **게이트2는 커밋을 다 모아 push 한 번으로 끝낸다** — squash 병합 커밋 → (있으면) 절차 문서 커밋 → handOff 커밋 → push 1회. **승인 요청 때 push할 커밋 건수를 먼저 알린다**(64차 = 코드 3건).
- **메인 세션은 서브에이전트의 수치를 그대로 옮기지 않고 직접 다시 잰다**(64차 — 이 방식으로 dev·QA 양쪽에서 결함을 잡았다). **일부 값은 일부러 알려주지 않고 독립 일치를 만든다.**
- **정본 명령은 쓰기 전에 표본으로 시험 실행한다**(64차 — 실제로 쓰기 전 3건을 잡았다). **서브에이전트는 메인 세션의 전제를 검증 없이 수용하지 않는다**(62~64차).
- **결과 XML 집계는 `is not None`으로 비교**하고 **스크립트·gradle `N failed`·XML 속성 합 3자 교차**를 확인한다(60차). **판정 단위는 케이스 FAIL 집합이고 exit code가 아니다.** **`--rerun-tasks` + XML mtime이 실행 창 안**(64차: 같은 초로는 구분이 안 돼 나노초로 찍는다).
- **같은 워킹트리에서 gradle을 동시에 돌리지 않는다**(58차). 동시 작업 시 `git archive {commit}`로 스크래치 사본을 뜬다.
- **실기동 — 브라우저 패널 제약 2건을 전제로 설계한다**(59차, 60·61차 재확인). ⓐ **네이티브 `confirm()`이 억제**된다 ⓑ OS 클릭이 전달되지 않는 상태가 생긴다. **로그인 판정은 서버 로그 `Secured` 줄·페이지 응답코드·화면의 로그인 표시로만 한다**(59차 오판).
- **`[파일 복사 완료] N`을 복사 수로 읽지 않는다** / **CRLF 5파일을 `sed -i`로 편집하지 않는다** / **mermaid 판정 렌더러는 GitHub 실화면(11.17.2)** / **레거시 문서에 파이프라인 문서 경로·사이클 슬러그를 인용하지 않는다**.
