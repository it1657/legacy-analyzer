## 1. 지금 시스템은 어떻게 동작하나 (핵심 사실)

| 항목 | 현재 사실 |
|---|---|
| Provider 선택 | **런타임 리졸버**(`LlmClientResolver`)가 DB `llm_model_options`의 `provider` 값으로 매 호출마다 구현체를 고른다. `llm.provider` 프로퍼티는 **DB에 없는 모델명에 대한 폴백 기본값**으로만 남아 있다 |
| 모델 목록 | DB(`llm_model_options`) + 관리자 CRUD(`/api/admin/llm-models`, ADMIN 전용). 사용자 조회는 `GET /api/config/llm-models`(**인증 필요** — 미인증은 302), 설치 여부는 `/local-installed`(TTL 캐시, `available=false`는 "설치 없음"이 아니라 **"확인 불가"**) |
| 접근 권한 | **Anthropic = 허가제**(API 키 설정 + `ANTHROPIC_USER` Role 보유자만, admin은 항상 통과) / **로컬 = 기본 개방**(활성 LOCAL 모델이 DB에 있으면) |
| 비상용(임시) 모델 목록 — **59차 신규** | 모델 목록 조회가 실패해 **하드코딩 임시 목록이 표시된 상태에서는 분석이 시작되지 않는다.** `runBatchAnalysis()`·`runUploadAnalysis()` **두 진입점 모두** 안내 alert 1회만 띄우고 `/api/start-analysis`를 호출하지 않는다(실기동 실측: 요청 0건) |
| 원본 소실 — **59차 신규** | `SessionSourceAvailability`가 재개 전에 원본 존재를 판정한다. **전량 소실이면 `reason:"SOURCE_MISSING"`으로 거부**하고(세션·이력 상태와 `pending_file_paths_json` **불변**), **일부 소실이면 남은 파일만 재개**하며 소실분은 실패로 기록한다(`missingCount`/`pendingCount` 응답). **분석 기록은 어느 경우에도 삭제하지 않는다.** 목록에는 `⛔ 원본 소실 — 재개 불가` / `⚠️ 원본 일부 소실 (n/m개)`를 **사전 표시**하고, 전량 소실 행에서는 재개 버튼을 렌더하지 않는다 |
| 종단 세션 보호 — **59차 신규** | 이미 끝난(COMPLETED/CANCELLED/FAILED) 분석에 대한 일시정지는 `reason:"SESSION_TERMINAL"`로 거부되고 **상태를 바꾸지 않는다.** 종단 분기의 status 저장 경로도 일원화됐다 |
| 전량 실패 — **59차 신규** | 전량 실패 세션도 `historyId`를 응답에 싣고 실패 원인 요약을 노출한다. PPT·보고서는 성공 0건이어도 생성된다(실서버 실측) |
| failover | 크레딧 소진 시 관리자가 지정한 대상 모델로 이어갈지 사용자 컨펌 — `AWAITING_FAILOVER_CONFIRM`(종료 상태 아님, 폴링 계속) |
| RAG | A안(패키지 구조 압축, `rag.enabled`) + B안(코드 내용 청킹·유사 코드 검색, `rag.content.enabled`) 독립 토글 2개 |
| 토큰 집계 | **세션 키 맵으로 격리돼 있다**(56차) — `ClaudeServiceImpl`이 `sourceFolderPath`를 키로 세션별 카운터를 들고, 조회·리셋·누적 전부 키를 받는다. `runAnalysis()` 시작 시 그 키만 리셋하고 **재개 경로는 리셋하지 않는다 — 일시정지 구간 토큰은 DB 어디에도 저장되지 않으므로 리셋하면 영구 소실되기 때문**이다. 키가 같으면(동일 경로 동시 분석) 여전히 같은 카운터에 합산된다(§4-B 이월) |
| 비용 계산 | **세션이 실제로 라우팅되는 provider로 판정한다**(56차). 판정은 `MainApiController.resolveEffectiveProvider()` 하나로 모으고 `ClaudeServiceImpl.resolveProvider()`와의 진리표 일치를 **계약 테스트로 고정**했다 |
| 모델 단가 — **결정** | `llm/AnthropicModelPricing`이 **정확 키 → `claude-` 접두 패밀리 → 미지 모델은 최고 단가(opus) + `log.warn`(모델키당 1회)** 순으로 결정한다(56차). **조용히 최저 단가로 떨어지지 않는다** |
| 모델 단가 — **표시** | **단가 문자열의 정본은 `AnthropicModelPricing` 한 곳뿐이다**(58차). API가 `pricing` 필드로 내려보내면 `dashboard.js`가 `표시명 · 단가`로 조립한다. **DB 표시명에는 단가를 적지 않는다** |
| 옛 표시명 자동 정리 | 기동 시 **옛 시드 원문과 `equals` 완전 일치하는 행만** 교체하고 건수를 로그에 남긴다(**0건도 찍힌다**). **관리자가 고친 행은 건드리지 않는다.** 멱등이다 |
| 토큰 추출 | 응답 파싱은 **각 `LlmClient` 구현체**가 한다 — Anthropic은 `input_tokens`/`output_tokens`/캐시 토큰 2종, OpenAI 호환은 `prompt_tokens`/`completion_tokens`(**캐시 토큰은 항상 0**). 둘 다 `LlmResult`로 정규화된다 |

### B. 코드 — 결함·의심 (정본은 `analyzer-plan/docs/pipeline/bug-suspects.md`, **상태 갱신은 PM 전결**)

| 우선 | 항목 | 요지 |
|---|---|---|
| **P1** | **58차 변경의 운영 DB 실데이터 검증이 배포 시점에만 가능하다** | 옛 표시명 자동 정리는 **새 H2 검증 DB에서만** 확인됐다. **배포 후 첫 기동 로그의 `[LLM 모델 표시명 정리]` 줄이 사실상 최종 검증**이다. ⚠️ **Windows 콘솔로 로그를 받으면 CP949로 떨어져 한글 grep이 구조적으로 0건**이 된다 — `--logging.charset.console=UTF-8`을 붙이거나 변환 후 grep(`-Dstdout.encoding`은 **실측상 무효**) |
| **P2** | **처리 수가 총계를 넘고 그 값이 DB에 저장된다(59차 관찰, 미수정)** | 재개가 이미 시도한 파일을 다시 처리하며 카운터를 **중복 가산**한다. 실기동 실측: 12파일 분석인데 `analysis_sessions.processed_files=15`, 화면 진행률 **125%**. **표시 문제가 아니라 영속 데이터의 모순**이라 이력·통계·재개 판단으로 전파된다. 반대 방향도 같은 뿌리다 — 일부 소실 시 소실분이 `processed`에 안 들어가 **75%에서 멈춘다** |
| **P2** | **실패 사유 집계가 `request_id` 때문에 무력화된다(59차 관찰, 미수정)** | 사유 키를 **메시지 전문**으로 잡아, 원인이 같아도 응답마다 다른 `request_id` 때문에 **N건이 N종으로** 집계된다. 사용자 안내가 1,000자를 넘고 request_id가 그대로 노출된다. **같은 실행 안에서 원인이 확정됐다** — `request_id`가 없는 사유(`원본 파일 없음`)는 5건이 **1종으로 정확히 묶였다**. 키를 `errorType`으로 잡으면 해소된다 |
| **P2** | **이력 테이블과 상태 API의 실패 건수가 어긋난다(59차 관찰, 미수정)** | 재개 이후 발생한 실패가 `analysis_history.failure_count`에 반영되지 않는다. 실측: 이력 **2** vs 상태 API **14**. **목록 화면은 이력 값을 보여준다** |
| **P2** | **사용자 일시정지를 "자동 일시정지"로 설명한다(59차 관찰, 미수정)** | 성공 0건이라는 조건만으로 전량 실패 배너를 띄운다. 서버 로그상 일시정지 호출은 사용자 요청 1건뿐인데 화면은 "전체 파일 처리 실패로 분석이 **자동** 일시정지되었습니다"라고 안내한다 — **사용자가 자기 조작을 장애로 오해한다** |
| **P2** | **동일 `sourceFolderPath` 동시 분석의 잔여 혼입** | 56차의 세션 키 격리는 **키가 다를 때만** 유효하다. 같은 경로로 두 분석이 동시에 돌면 같은 카운터에 합산된다 |
| **P2** | **JVM 재시작 후 재개 시 토큰 소실** | 카운터가 인메모리이고 영속화가 없다 |
| **P2** | **세션 중 failover 시 Anthropic 토큰이 0원으로 계산됨** | `calculateEstimatedCost()`가 **finalize 시점의 최종 모델명 기준**으로 전체를 계산한다. 세션 단위 provider 이력이 필요하다 |
| **P2** | **JS 주석 통과 구멍** | 단일 출처 계약 테스트의 `dashboard.js` 존재 검사가 **주석 속 토큰과 실제 호출을 구별하지 못한다**(gradle 전건 GREEN인데 node 하네스만 잡는다). 문자열·정규식 리터럴 안의 `//`·`/*` 처리가 필요해 별도 설계 대상 |
| **P2** | **gradle `:test` 입력 선언 공백** | 계약 테스트가 런타임에 `src/main`을 읽는데 `build.gradle`의 `test`/`qaTest`에 그 디렉터리가 **선언된 입력이 아니다.** 해소 전까지 **증거로 쓰는 실행은 `--rerun-tasks` 필수**다(G-16). `build.gradle` 편집이 필요해 인프라 사이클 대상 |
| **P2** | **관리자 목록 `renderLlmModels()`의 innerHTML 미이스케이프** | 사람이 **"확인됨, 당장 수정하지 않음"으로 결정**(2026-09-30) |
| **P2** | 서버측 시작 시점 검증(B안) 부재 | `ClaudeServiceImpl.setModel()`이 DB 활성 등록만 보고 **설치 여부는 안 본다** — 직접 API 호출은 막히지 않는다 |
| **P2** | 취소 후 진행 중이던 LLM 요청이 중단되지 않음 | `cancelAnalysis()` 뒤에도 생성이 수 분간 이어졌다. **관측만 있고 등록 안 됨** |
| **P2** | A안 가용성 회귀의 처분 | Ollama가 죽으면 설치된 로컬 모델로도 분석 시작 불가. 게이트1에서 사람이 택한 **의도된 대가** |
